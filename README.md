# DSH Setup для macOS

Локальный мастер установки пользовательской конфигурации DeepSeek Harness и Oh My DSH Slim. **Это не дистрибутив приложения DeepSeek Harness.**

## Установка

Откройте «Терминал» и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/egor-malishevski/dsh-installer/main/install.sh | bash
```

Если DeepSeek Harness ещё не установлен, скрипт сначала скачивает официальную сборку 0.2.1-rc.5 для Apple Silicon с `download.deepseek.com` (около 350 МБ). Затем сверяет SHA-512 с суммой из фида обновлений DeepSeek, проверяет версию, bundle ID и подпись DeepSeek (Team `NAN929V4UM`) и кладёт приложение в `/Applications`. Уже установленное приложение скрипт не изменяет. Если его версия отличается от 0.2.1-rc.5, выводится предупреждение. DeepSeek удаляет старые сборки, поэтому после выхода новой версии загрузка rc.5 может перестать работать. Для Mac на Intel сборки 0.2.1-rc.5 нет.

Затем скрипт скачивает архив мастера из GitHub Releases, сверяет его SHA-256 с суммой, записанной в `install.sh`, распаковывает во временную папку и открывает мастер в браузере. Когда установщик закрывается, временная папка удаляется. Права администратора (`sudo`) не нужны.

Если нужно только проверить окружение, без запуска мастера:

```bash
curl -fsSL https://raw.githubusercontent.com/egor-malishevski/dsh-installer/main/install.sh | bash -s -- --check
```

### Почему не нужны подпись и Apple Developer

Мастер только настраивает официальный DeepSeek Harness. Само приложение скачивается с сервера DeepSeek без изменений, подписано и нотаризовано DeepSeek, и установщик его не изменяет. Gatekeeper проверяет файлы с атрибутом карантина, а его получают файлы, скачанные браузером. У файлов, загруженных через `curl`, этого атрибута нет, поэтому macOS не блокирует запуск.

### Установка из архива

Скачайте `dsh-installer-<версия>.tar.gz` со страницы Releases, распакуйте архив и выполните `bash Install.command` в папке распаковки. Если архив скачан браузером, двойной клик по `Install.command` macOS заблокирует. Явный запуск через `bash` работает. Мастеру всё равно требуется подключение к CLIProxyAPI для получения списка моделей.

### Для разработчика

`npm test` запускает тесты. `npm run package` собирает `dist/dsh-installer-<версия>.tar.gz`, файл `.sha256` и записывает версию и сумму в `install.sh`. Архив загружается в Release с тегом `v<версия>`, затем коммитится обновлённый `install.sh`.

## Требования

- macOS на Apple Silicon и официальный **DeepSeek Harness 0.2.1-rc.5** в `/Applications/DeepSeek Harness.app`. Если приложения нет, команда установки скачает его сама.
- Harness обновляется автоматически. Мастер принимает только 0.2.1-rc.5, а работа установленной конфигурации на более новых версиях не проверялась.
- Собственный CLIProxyAPI: адрес API и API Key. Пароль панели управления CLIProxyAPI — не API Key.
- Первичная установка — только на чистый профиль Desktop; перезаписи существующей конфигурации она не выполняет. Обновление существующей установки поддерживает отдельный режим (см. «Режим обновления»). Совместимость приложения: `0.2.1-rc.5`, bundle `com.deepseek.dsh`.
- Для выбранных MCP могут потребоваться дополнительные программы, доступ к сети и отдельная авторизация.

Версия Harness закреплена из-за локального клиента наблюдения за соединениями MCP. При обновлении Harness совместимость нужно проверить заново.

## Порядок настройки

1. Разверните CLIProxyAPI по [инструкции Render / Git Storage](https://help.router-for.me/hands-on/tutorial-10.html). Репозиторий с конфигурацией и авторизацией должен быть **приватным**. GitHub-токен и пароль управления вводятся на стороне сервиса, а не в этом мастере.
2. Введите API URL и API Key вашего CLIProxyAPI и проверьте настройки. Мастер обязательно запрашивает `GET /v1/models` и предлагает только модели из полученного списка. Этот запрос нужен для проверки URL/ключа и подбора ролей. Профиль содержит начальный список моделей: известный каталог плюс модели, найденные при установке (неизвестные получают мультимодальный вход, без reasoning). Автоматического обновления списка на закреплённой версии `0.2.1-rc.5` нет: чтобы подтянуть новые модели CLIProxyAPI, откройте в Harness **Settings → Models → Fetch available models** и нажмите **Save**.
   **Ключ CLIProxyAPI.** Профиль ссылается на ключ через `apiKeyEnv: CLIPROXY_API_KEY`; заголовков `Authorization` и `!!js` для ключа нет. Если `~/.dsh/.credentials.yaml` отсутствует, установщик создаёт его (режим `0600`, формат YAML `version: 1` и `refs.CLIPROXY_API_KEY`) — в профиль и журналы ключ не попадает. Если файл уже есть, установщик **не читает, не дополняет и не перезаписывает** его и ключ не записывает: в предупреждениях проверки и на финальном экране появится требование открыть **Settings → Models → CLIProxyAPI**, ввести ключ в поле учётных данных и нажать **Save**. Пока этого не сделано, запросы к CLIProxyAPI авторизованы не будут.
3. Выберите необходимые MCP и задайте новые параметры. По умолчанию ни один MCP не выбран. GitLab и Bitbucket можно выбрать независимо, в том числе вместе.
4. Проверьте автоматически подобранные роли и модели Oh My DSH Slim и при необходимости измените их.
5. Закройте Harness через **⌘Q**, выполните проверки и подтвердите установку.

При неверных учётных данных, ошибке запроса или пустом списке моделей установка блокируется. Перед записью мастер повторно получает список: если выбранные модели больше недоступны, он попросит повторить проверку и выбор. Запрос списка не проверяет выполнение запросов к модели; авторизуйте нужные аккаунты на стороне CLIProxyAPI.

## Начальные назначения

Мастер детерминированно подбирает роли из обнаруженного каталога, предпочитая подходящие известные модели и используя доступный вариант, если предпочтительных нет. Все роли, включая Explorer, используют CLIProxyAPI; Orchestrator наследует основную модель. Проверьте модели и доступные уровни reasoning перед установкой.

Общие разрешения ролей ограничиваются выбранными MCP и конкретными инструментами чтения. Они не создают отдельных подключений. Designer получает чтение макетов Figma (`get_figma_data`), Explorer и Librarian — поиск документации Context7. Obscura, Memory, Google Sheets и Sequential Thinking остаются у основной сессии. GitLab настраивается в режиме `readonly`.

Для Figma нужен персональный токен Figma. API-ключ Context7 необязателен: без него действуют бесплатные лимиты запросов.

## Локальные улучшения Oh My DSH Slim

Payload содержит доработанную версию Slim 0.8.7:

- У исполнителей скрыты делегирование, управление другими агентами, goal и plan-mode. `send_message` сохранён для отчёта родителю. Ограничения добавляются к пользовательским, а не заменяют их.
- Промпты требуют `glob`/`grep`/`read` для поиска и чтения, `write` для новых файлов и `edit` для изменений. Запрещено обходить отказ файлового инструмента через shell. Это инструкция модели, **не технический фильтр команд bash**.
- Explorer сохраняет bash для немутирующей диагностики; read-only — назначение роли, а не полноценная изоляция от записи через shell. Выданные MCP отдельно ограничиваются списками инструментов.
- Ограниченные UI/E2E-проверки поручаются Fixer с заданными критериями и доступными инструментами; validation-only задачи не разрешают менять исходники. Отдельная QA-роль и дополнительный MCP автоматически не устанавливаются.
- Librarian начинает с Context7 для библиотек/API и загружает целевые источники вместо массового перебора URL. Уточнена дисциплина goal-инструментов оркестратора.

- **Цепочки fallback (`0.8.7-native.1`, готово, без live-smoke).** Пять специалистов (oracle, designer, fixer, explorer, librarian) могут иметь до 3 fallback `{provider, model, effort?}`. Повтор выполняется на том же шаге LLM через hooks, subagent заново не запускается. Council и orchestrator fallback не получают. Триггеры: квота, rate limit, ошибки сервера, таймауты, транспорт, пустой ответ, неизвестная ошибка, PIAI; отмена учитывается; AUTH и невалидный контекст не поддерживаются. Effort основной модели сохраняется, у fallback отбрасывается, если не задан явно. Подробности, таймауты и cooldown — в [README плагина](payload/plugins/oh-my-dsh-slim/README.md#fallback-chains-native-line). Основная модель вне Slim: без дополнительной очистки в уже мигрированной установке остаётся `fallback-main`; в свежей установке main — реальная модель. **Нативного автоматического fallback для main нет**, поэтому покрытие всех ролей не заявляется. Миграция существующих настроек (`migrateNativeFallbacks`) описана в разделе «Режим обновления».

Изменения уже входят в устанавливаемый payload. `scripts/prepare-payload.js` проверяет обязательные запреты и маркер файловой политики: неподготовленная upstream-копия не должна незаметно затереть доработки. При обновлении Slim перенесите изменения и прогоните `npm test`. После замены установленного плагина требуется полный выход из DSH и повторный запуск; уже работающие агенты не считаются обновлёнными.

## Веб-поиск через Exa и Parallel

Устанавливаемый провайдер `web_search` использует Exa без API-ключа и при ошибке или отсутствии результатов автоматически переключается на Parallel. Переключение включено всегда. Квоты сервисов не опубликованы, SLA нет; бесплатная неограниченная работа не гарантируется. Результаты зависят от доступности сервисов. `web_fetch` по-прежнему загружает страницы напрямую по HTTP.

## Что не переносится

- Корпоративные плагины и провайдеры исходного компьютера, а также их ключи.
- Личные API-ключи, корпоративные адреса и учётные данные исходного компьютера.
- Сессии, журналы, сохранённая Memory, cookies и браузерный профиль Obscura.
- Настройки OpenCode, бинарник Harness и содержимое `app.asar`.

Мастер работает локально на `127.0.0.1`. Доступ к его API защищён случайным токеном текущего запуска. Не пересылайте адрес открытого мастера. Ключи не должны попадать в скриншоты, URL или журналы. После работы закройте вкладку и остановите установщик в терминале через `Ctrl+C`.

## Режим обновления

Режим обновления доступен в API, сервере и UI мастера. Это не отменяет требование «чистый профиль» для первичной установки.

- Остановите старый установщик в терминале через **Ctrl+C**, затем запустите новый через `bash Install.command`. Перед apply закройте Harness через **⌘Q**. Сборщик `APP_RUNNING` использует команды процессов без окружения и исключает точный запуск установщика; настоящие процессы GUI/main host и процессы всех профилей блокируют применение консервативно.
- **Preview:** `POST /api/update` с `{dryRun:true}`. Ничего не пишет и работает при открытом приложении. Результат: `actions`, `needsAck`, `details`, `conflicts`, `planHash`.
- **Apply:** `{dryRun:false, planHash, acknowledgeManagedFiles:true}`. Приложение должно быть закрыто (⌘Q). Проверяется окружение: поддерживается только `0.2.1-rc.5`, `com.deepseek.dsh`.
- Блокировка (lock), резервная копия (каталог `0700`, файлы `0600`, manifest с метаданными), атомарные записи и откат при ошибке.
- Сохраняются пользовательские строки, модели, bundles; секреты не читаются. Без очистки существующие алиасы Relay сохраняются без перезаписи.
- Конфликтующие версии блокируют обновление, кроме явного перехода `0.8.7` → `0.8.7-native.1`.
- Ремонт `MANIFEST` зависимостей: только закреплённые версии (pins); `npm run` и реальный установщик зависимостей не выполняются. Существующий lockfile считается конфликтом.
- **Патч профиля:** поддержка блочного YAML ограничена. Изменяются только нужные диапазоны исходника без пересериализации всего документа; комментарии и неизвестные скалярные JS-теги сохраняются без вычисления. Необработанные строки непрозрачных тегов проверяются на известные буквальные ссылки fallback, но теги не вычисляются: это не полная поддержка YAML. Неподдерживаемые конструкции, в том числе некоторые затрагиваемые flow-конструкции, отклоняются с `PATCH_YAML_UNSUPPORTED` без записи. Изменение существующей последовательности fallback, затрагиваемые многострочные значения или пустые коллекции с комментариями также могут вызвать этот отказ. Поведение JSON не меняется. Парсер `yaml` 2.8.3 закреплён в `lib/vendor`, с лицензией ISC и указанием происхождения.
- **Миграция fallback.** Необязательный `migrateNativeFallbacks` по умолчанию `false` и входит в `planHash`. Он переносит известные алиасы пяти ролей cliproxy в нативные конфигурации с упорядоченными fallback; при выключенной очистке `fallback-main` и YAML-алиасы остаются без изменений. Требуется capability `0.8.7-native.1`; транзакция включает плагин и профиль с откатом.
- **Очистка Relay (новое в 1.3.3).** Отдельный чекбокс UI выключен по умолчанию; его включение подразумевает нативную миграцию. В UI выберите реальную модель main, например `gpt-6.1-sol`: замена `fallback-main` требует явного выбора модели из каталога, иначе возникает конфликт; существующая реальная main сохраняется. Для main автоматического fallback нет. Все шесть известных алиасов каталога удаляются только при отсутствии других ссылок. Изменённый Relay fallback заменяется обычным zstd proxy только при известном хеше старой версии; неизвестный пользовательский вариант вызывает конфликт, а уже совпадающий обычный payload пропускается. Для шести известных алиасов каталога поддерживается удаление из блочного и flow YAML с использованием CST и диапазонов исходника; scalar main можно заменить. Удаляемые блочные участки с комментариями отклоняются. Во flow любой символ `#` консервативно вызывает отказ, даже внутри строки в кавычках. Весь документ не пересериализуется; непрозрачные участки вне изменений сохраняются без вычисления. Очистка выполняется при остановленном приложении в транзакции с резервной копией, подтверждением и проверкой `planHash`.
- **Ключи 1.3.11.** Обновление преобразует существующий JSON-файл `~/.dsh/.credentials.yaml`, который DSH может прочитать, но не может сохранить. Обычный YAML не изменяется.
- **Ключи 1.3.10.** Обновление теперь действительно читает `~/.dsh/.credentials.yaml` и преобразует точный JSON-файл прежнего установщика в YAML.
- **Ключи 1.3.9.** Новое хранилище `~/.dsh/.credentials.yaml` записывается как YAML, который текущий DSH может сохранять. Обновление преобразует только точный JSON-файл прежнего установщика; остальные хранилища не изменяются.
- **Очистка 1.3.8.** Включённая очистка больше не блокирует обновление, если установленный relay — известный исходный файл без явного upstream: такой файл сохраняется. Неизвестный relay по-прежнему остаётся конфликтом. Замена исходного relay выполняется только при явном корректном upstream и подтверждении.
- **Полное обновление 1.3.7.** Если не хватает только одной локальной `link:`-зависимости, установщик дописывает её в `pnpm-lock.yaml` версии 9 и не переписывает остальные записи. Другие lock-файлы и непонятный формат по-прежнему блокируются. Исходный обычный relay без явного upstream сохраняется при выключенной очистке; замена по-прежнему требует подтверждения и явного upstream.
- **Исправление 1.3.6.** В 1.3.5 страница мастера оставалась на «Загрузка…» из-за синтаксической ошибки в отрисовке плана обновления. Логика обновления не менялась.
- **Режим «Только Slim» (1.3.5).** Перед предпросмотром нужно явно выбрать состав: «Только Oh My DSH Slim» или «Все компоненты». Slim обновляет только уже установленный `oh-my-dsh-slim` и не читает relay, bundle, web-search и lock-файл. Манифест профиля, `pnpm-lock.yaml`, relay, bundle и основная модель не меняются. Отсутствующий Slim не устанавливается (`SLIM_NOT_INSTALLED`); чужая ссылка, неверная версия или изменившиеся зависимости плагина блокируют обновление. Очистка relay и выбор основной модели в этом режиме недоступны. Отдельная галочка «Добавить резервы» по умолчанию выключена и в обоих составах добавляет fallback только специалистам без собственного поля `fallbacks`; явный список, в том числе пустой, основная модель, усилие и инструменты роли сохраняются. Неоднозначные слои конфигурации отклоняются целиком. Изменение профиля после предпросмотра требует нового плана. Состав «Все компоненты» по-прежнему может чинить зависимости и блокируется существующим lock-файлом.
- **Совместимость 1.3.4:** абсолютные и относительные `link:`-ссылки, разрешающиеся в ожидаемый путь текущего домашнего каталога, сохраняются как записаны; чужой путь остаётся конфликтом. Очистка также распознаёт исходный обычный Relay по закреплённому SHA-256 `77058099982aa362047ff7e565dbc7641783ad507c62bbfbc2fa719479c4cccd`: замена с подтверждением разрешена только для одной управляемой записи с ожидаемыми ID, именем и путём и одного потребителя нормализованного пути. Нужен явный обычный HTTP(S) upstream; тегированные ID, имя или upstream блокируются с `RELAY_UPSTREAM_REQUIRED`, как и отсутствие допустимого upstream. Дублирующие потребители блокируют очистку; посторонние `!!js`-значения авторизации сохраняются. Неизвестные хеши по-прежнему вызывают конфликт, произвольного разрешения хешей или принудительной замены нет; совпадающий обычный payload пропускается.
- **Чего не делает:** не обновляет приложение, не запускает пакетные менеджеры.

Нативное обновление проверено на реальном профиле после установки; эта проверка не подтверждает реальные запросы к моделям или срабатывание fallback. Очистка проверена только на временных фикстурах, не применялась live. Сервер проверен локальными тестами; 25 браузерных runtime-тестов пропущены из-за отсутствия Playwright, полного E2E нет. Нормальный откат проверен на временном каталоге; contract tool replay не заменяет проверку реального Harness. После сбоя см. [восстановление после сбоя обновления](docs/update-recovery.md).
