# DSH Setup для macOS

Локальный мастер установки пользовательской конфигурации DeepSeek Harness и Oh My DSH Slim. **Это не дистрибутив приложения DeepSeek Harness.**

## Установка

Откройте «Терминал» и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/egor-malishevski/dsh-installer/main/install.sh | bash
```

Если DeepSeek Harness ещё не установлен, скрипт сначала скачивает официальную сборку 0.2.1-rc.5 для Apple Silicon с `download.deepseek.com` (около 350 МБ). Затем сверяет SHA-512 с суммой из фида обновлений DeepSeek, проверяет версию, bundle ID и подпись DeepSeek (Team `NAN929V4UM`) и кладёт приложение в `/Applications`. Уже установленное приложение скрипт не изменяет. Если его версия отличается от 0.2.1-rc.5, выводится предупреждение. DeepSeek удаляет старые сборки, поэтому после выхода новой версии загрузка rc.5 может перестать работать. Для Mac на Intel сборки 0.2.1-rc.5 нет.

Затем скрипт скачивает архив мастера из GitHub Releases, сверяет его SHA-256 с суммой, записанной в `install.sh`, распаковывает во временную папку и открывает мастер в браузере. Когда установщик закрывается, временная папка удаляется. Права администратора (`sudo`) не нужны.

Если нужно только проверить окружение, без запуска мастера:

```bash
curl -fsSL https://raw.githubusercontent.com/egor-malishevski/dsh-installer/main/install.sh | bash -s -- --check
```

### Почему не нужны подпись и Apple Developer

Мастер только настраивает официальный DeepSeek Harness. Само приложение скачивается с сервера DeepSeek без изменений, подписано и нотаризовано DeepSeek, и установщик его не изменяет. Gatekeeper проверяет файлы с атрибутом карантина, а его получают файлы, скачанные браузером. У файлов, загруженных через `curl`, этого атрибута нет, поэтому macOS не блокирует запуск.

### Установка из архива

Скачайте `dsh-installer-<версия>.tar.gz` со страницы Releases, распакуйте архив и выполните `bash Install.command` в папке распаковки. Если архив скачан браузером, двойной клик по `Install.command` macOS заблокирует. Явный запуск через `bash` работает. Мастеру всё равно требуется подключение к CLIProxyAPI для получения списка моделей.

### Для разработчика

`npm test` запускает тесты. `npm run package` собирает `dist/dsh-installer-<версия>.tar.gz`, файл `.sha256` и записывает версию и сумму в `install.sh`. Архив загружается в Release с тегом `v<версия>`, затем коммитится обновлённый `install.sh`.

## Требования

- macOS на Apple Silicon и официальный **DeepSeek Harness 0.2.1-rc.5** в `/Applications/DeepSeek Harness.app`. Если приложения нет, команда установки скачает его сама.
- Harness обновляется автоматически. Мастер принимает только 0.2.1-rc.5, а работа установленной конфигурации на более новых версиях не проверялась.
- Собственный CLIProxyAPI: адрес API и API Key. Пароль панели управления CLIProxyAPI — не API Key.
- Чистый профиль Desktop. Установщик не предназначен для перезаписи или обновления существующей сборки.
- Для выбранных MCP могут потребоваться дополнительные программы, доступ к сети и отдельная авторизация.

Версия Harness закреплена из-за локального клиента наблюдения за соединениями MCP. При обновлении Harness совместимость нужно проверить заново.

## Порядок настройки

1. Разверните CLIProxyAPI по [инструкции Render / Git Storage](https://help.router-for.me/hands-on/tutorial-10.html). Репозиторий с конфигурацией и авторизацией должен быть **приватным**. GitHub-токен и пароль управления вводятся на стороне сервиса, а не в этом мастере.
2. Введите API URL и API Key вашего CLIProxyAPI и проверьте настройки. Мастер обязательно запрашивает `GET /v1/models` и предлагает только модели из полученного списка. Этот запрос нужен для проверки URL/ключа и подбора ролей; после установки список моделей на закреплённой версии `0.2.1-rc.5` обновляет плагин `cliproxy-models` (см. ниже) — без перезапуска, каждые 5 минут, таймаут 5 с. Статический список в профиле — только метаданные (название, вход, reasoning) и последний известный список до первой синхронизации. Новые модели CLIProxyAPI появляются автоматически; неизвестные получают метаданные по умолчанию (мультимодальный вход, без reasoning). Ключи `discoverModels`/`modelsMaxAgeMs`/`modelsTimeoutMs` в профиле на `0.2.1-rc.5` игнорируются; сборки Harness с обнаружением на уровне маршрута будут использовать их сами, а плагин в этом случае засыпает.
3. Выберите необходимые MCP и задайте новые параметры. По умолчанию ни один MCP не выбран. GitLab и Bitbucket можно выбрать независимо, в том числе вместе.
4. Проверьте автоматически подобранные роли и модели Oh My DSH Slim и при необходимости измените их.
5. Закройте Harness через **⌘Q**, выполните проверки и подтвердите установку.

При неверных учётных данных, ошибке запроса или пустом списке моделей установка блокируется. Перед записью мастер повторно получает список: если выбранные модели больше недоступны, он попросит повторить проверку и выбор. Запрос списка не проверяет выполнение запросов к модели; авторизуйте нужные аккаунты на стороне CLIProxyAPI.

## Начальные назначения

Мастер детерминированно подбирает роли из обнаруженного каталога, предпочитая подходящие известные модели и используя доступный вариант, если предпочтительных нет. Все роли, включая Explorer, используют CLIProxyAPI; Orchestrator наследует основную модель. Проверьте модели и доступные уровни reasoning перед установкой.

Общие разрешения ролей ограничиваются выбранными MCP и конкретными инструментами чтения. Они не создают отдельных подключений. Designer получает чтение макетов Figma (`get_figma_data`), Explorer и Librarian — поиск документации Context7. Obscura, Memory, Google Sheets и Sequential Thinking остаются у основной сессии. GitLab настраивается в режиме `readonly`.

Для Figma нужен персональный токен Figma. API-ключ Context7 необязателен: без него действуют бесплатные лимиты запросов.

## Локальные улучшения Oh My DSH Slim

Payload содержит доработанную версию Slim 0.8.7:

- У исполнителей скрыты делегирование, управление другими агентами, goal и plan-mode. `send_message` сохранён для отчёта родителю. Ограничения добавляются к пользовательским, а не заменяют их.
- Промпты требуют `glob`/`grep`/`read` для поиска и чтения, `write` для новых файлов и `edit` для изменений. Запрещено обходить отказ файлового инструмента через shell. Это инструкция модели, **не технический фильтр команд bash**.
- Explorer сохраняет bash для немутирующей диагностики; read-only — назначение роли, а не полноценная изоляция от записи через shell. Выданные MCP отдельно ограничиваются списками инструментов.
- Ограниченные UI/E2E-проверки поручаются Fixer с заданными критериями и доступными инструментами; validation-only задачи не разрешают менять исходники. Отдельная QA-роль и дополнительный MCP автоматически не устанавливаются.
- Librarian начинает с Context7 для библиотек/API и загружает целевые источники вместо массового перебора URL. Уточнена дисциплина goal-инструментов оркестратора.

Изменения уже входят в устанавливаемый payload. `scripts/prepare-payload.js` проверяет обязательные запреты и маркер файловой политики: неподготовленная upstream-копия не должна незаметно затереть доработки. При обновлении Slim перенесите изменения и прогоните `npm test`. После замены установленного плагина требуется полный выход из DSH и повторный запуск; уже работающие агенты не считаются обновлёнными.

## Синхронизация моделей (`cliproxy-models`)

Плагин `~/.dsh/plugins/cliproxy-models/index.js` подключается установщиком рядом с relay. Он без импортов пакетов Harness:

- Через 5 минут (`intervalMs`, первый запуск — сразу после активации) запрашивает список моделей CLIProxyAPI (`ctx.llm.discoverModels`, с авторизацией маршрута, таймаут 5 с) и обновляет `providers.cliproxy.models` настроек `llm-pi-ai` без перезапуска.
- Порядок — как в ответе CLIProxyAPI; метаданные берутся из seed установщика (приоритет), затем из текущей записи (пользовательские поля вроде `contextWindow` сохраняются); неизвестные id получают `input: ['text','image']`.
- Закреплённые модели не пропадают, даже если их нет в списке: `pinned` из конфигурации, модель `agent-default-model` и модели ролей/оркестратора Oh My DSH Slim с провайдером `cliproxy`.
- Ошибка, таймаут или пустой ответ ничего не меняют (одно предупреждение на серию сбоев); пустой список никогда не записывается; конфликт ревизии повторяется на следующем цикле. Без изменений запись не выполняется.
- Если схема `llm-pi-ai` сама поддерживает `discoverModels` и он включён на маршруте, плагин не работает.

## Веб-поиск через Exa и Parallel

Устанавливаемый провайдер `web_search` использует Exa без API-ключа и при ошибке или отсутствии результатов автоматически переключается на Parallel. Переключение включено всегда. Квоты сервисов не опубликованы, SLA нет; бесплатная неограниченная работа не гарантируется. Результаты зависят от доступности сервисов. `web_fetch` по-прежнему загружает страницы напрямую по HTTP.

## Что не переносится

- Корпоративные плагины и провайдеры исходного компьютера, а также их ключи.
- Личные API-ключи, корпоративные адреса и учётные данные исходного компьютера.
- Сессии, журналы, сохранённая Memory, cookies и браузерный профиль Obscura.
- Настройки OpenCode, бинарник Harness и содержимое `app.asar`.

Мастер работает локально на `127.0.0.1`. Доступ к его API защищён случайным токеном текущего запуска. Не пересылайте адрес открытого мастера. Ключи не должны попадать в скриншоты, URL или журналы. После работы закройте вкладку и остановите установщик в терминале через `Ctrl+C`.

## Состояние разработки

Сборка ещё проходит интеграцию и не объявлена готовой к установке на другой компьютер. До итоговой проверки не используйте её для рабочего профиля. Завершённые проверки отдельных компонентов не заменяют проверку полного пути установки.

## Лицензии

Лицензии сторонних компонентов сохранены в `payload`, включая MIT-лицензии Oh My DSH Slim и встроенной копии MCP-клиента DeepSeek. Локальная интеграция включена как часть пользовательской сборки; это не заявление о лицензии на публичное распространение. Дополнительные MCP загружаются или устанавливаются отдельно и имеют собственные лицензии.
